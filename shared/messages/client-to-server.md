## 已实现行为（与服务端约定对齐）

1. 成功判定：`HTTP 200 且 code == 0` 视为成功；其余一律按失败展示服务端 `msg`，客户端不自行改写文案。
2. 响应输出：JSON 原样输出，仅 `token`、`key`、`license_key`、`password` 字段替换为 `***`（递归处理嵌套对象与数组）。
3. HTTP 状态：`422 / 403 / 429` 的 JSON body 原样输出（敏感字段遮蔽），退出码 0；HTTP 5xx 或非 JSON 响应只输出固定文案（`服务器内部错误` / `服务器拒绝访问` / `请求参数不合法` / `请求过于频繁` / `接口不存在` / `服务器返回内容无法解析`），5xx 退出码 1，其余 0。
4. 网络错误统一输出 `{"code":-1,"msg":"连接服务器失败"}`，退出码 0；参数不足输出 `{"code":-1,"msg":"参数不足"}`，退出码 0。
5. 编码：UTF-8，无 BOM，中文不转义。
6. 客户端不记录日志、不落盘 token/卡密，请求体字节用完即 `ZeroMemory`。

## 需要服务端确认 / 说明的 4 点

1. **machine_code 由调用方（主程序）生成并传入，客户端不生成**（项目安全红线第 7 条）。`server-to-client.md` 第 3 条写的是「客户端自行生成」——客户端不会实现生成逻辑，只把命令行传入的 1-128 字符值原样放进 `machine_code` 字段。
   → 请服务端保持「原样比对、不做格式校验」的行为，双方即可对接；如主程序需要指纹算法，请与主程序一侧约定，客户端不参与。
2. **卡密不做本地正则预校验**：客户端把用户输入的卡密原样发送，格式/有效性由服务端返回的 `code/msg` 表达。若你们希望客户端提前拦截非法格式，请明确回复，我再加（当前为空值/全空白按「参数不足」处理）。
3. **429 不做自动重试**：`checkpoint.exe` 是单次命令行调用（调用方可能是游戏/主程序），触发限流时直接把服务端 `msg` 输出并退出，退出码 0，不会在循环里重试 `/activate`。退避由上层调用方决定。
4. **默认地址差异（不影响对接）**：契约里本地地址是 `http://127.0.0.1:8080`，客户端配置缺失时按需求使用默认值 `http://localhost:8080`；两者都是回环地址。若要求完全一致，请回复「改 127.0.0.1」，我改成与契约一致。
